# S5 readiness after S4

S4a and S4b bounded synthetic proof acceptance are complete. The S4 publication
checkpoint includes their product source, local migration, tests and evidence.
The implementation can proceed to S5 locally when the user asks to start it.
Publishing S4 does not itself authorize S5 implementation or media inference.

## S5 scope

Reuse the owner flow and Kopi design. Segment one owner-supplied real dish photo
with SAM 3.1, generate one optional Muse Image decorative background, and compose
exact approved public offer text outside the model. Show source, mask/cutout,
background and owner approval. Food pixels come from the source. Generated
background is labeled; changed terms invalidate the promotional version. Booking
must work if media generation is unavailable. No new editor or poster variants.

## Prerequisites for genuine proof

- A rights-cleared dish photo and approved public offer terms. Synthetic fixtures
  can start engineering checks; they cannot prove photo rights or merchant demand.
- Confirm current SAM/Image request/output contracts read-only before pinning a
  live run. S0 found catalog entries but did not prove their media outputs.
  SAM's documented stream contains geometry/mask data, not a ready-made PNG;
  decoding and source-pixel composition still need implementation and proof.
- Prepare exact media inputs, model IDs, maximum attempts, response limits,
  no-retry guard and verified spend ceiling before requesting live-call approval.
  All prior S3/S4 allowances are consumed and unavailable to S5.

Production migration/deployment remains separate: 0015/0016 have only local proof.
S5 can use disposable local PostgreSQL without production access. No production
rollout, installs/downloads, paid call, real publication, or video is authorized
by this readiness note. Merchant validation and video remain user-owned.
