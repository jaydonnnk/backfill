Proposed build

Keep the main story small

  • One offer: café, visit window, price and minimum diners.
  • One visual: bookings fill seats toward the minimum.
  • One main action: “Watch how it works”, then “Replay”.
  • One result: confirmed diners and this group’s savings.
  • Kopi gives one short cue when something changes.

Put supporting information below

  • Collapse buyer records and timestamped events.
  • Move all-time savings and revenue splits into details.
  • Show Wonder’s next-offer suggestion as an optional follow-up.
  • Keep the separate real Muse booking as supporting evidence, never mix its totals into this scene.
  • Keep the existing Kopi colours, pixel headings and larger body text when styling.

States the design must handle

Waiting → bookings arrive → minimum reached → deadline passes → confirmed result or minimum not met. Reaching the minimum is not the same as a confirmed booking. Requested diners and confirmed diners remain distinct when capacity limits apply.

Also cover: sold out, disconnected feed, unavailable data, no recorded scene, and reduced-motion replay. Show unavailable savings as unavailable, not zero.

Implementation order

  1. Approve the layout direction.
  2. Replace the presentation using the existing live feed, saved bookings and replay behaviour.
  3. Move secondary information into details, then style within the current Kopi design.
  4. Check mobile/desktop, keyboard access, replay, deadline transitions, capacity and unavailable states on localhost.

Planning only. No changes to the live page or booking logic have been made.
